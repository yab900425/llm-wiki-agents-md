# 來源衝突與處理紀錄
原則：官方文件優先於第三方文章與搜尋結果摘要；看起來矛盾時先確認是不是「說的範圍不同」。

## C1　Claude Code 到底讀不讀 AGENTS.md？
- 一開始：搜尋結果的摘要寫「Claude Code 讀 CLAUDE.md，不讀 AGENTS.md」，另一篇 2025 年的第三方文章也說 Claude Code 當時未支援。
- 完整讀官方文件（S4）後：Claude Code 可以讀 AGENTS.md（v2.1.277 以上），預設只在找不到 CLAUDE.md 時才讀。
- 處理：採用 S4。舊說法視為過時，**不寫進 wiki 與簡報**。
- 教訓：搜尋摘要只能找網址，不能當事實（這條因此寫進 AGENTS.md 核心規則第 2 點）。

## C2　agents.md 官網沒列 Claude Code
- S2 的支援工具清單沒有 Claude Code，頁面也沒提到 CLAUDE.md；S4 卻說 Claude Code 可讀 AGENTS.md。
- 處理：不算矛盾。S2 的 logo 清單只是「頁面列出的工具」，不是完整名單；S4 是 Claude Code 自己的文件。簡報寫成「官網清單沒列出，但 Claude 官方文件寫明可讀」，兩邊都照實呈現。

## C3　Codex 的大小限制：32 KiB 還是 65536？
- 第三方課程頁說「到 32 KiB 就停止」；官方範例把 project_doc_max_bytes 設成 65536。
- 處理：以 S5 為準：**預設 32 KiB，範例把它調高到 65536**。兩個數字講的是預設值與範例設定，不衝突。

## C4　GitHub 文章（S3）內部不一致
- 標題／小節寫「六種 agent」，實際只描述五種；agents.md 與 agent.md 混用；dev-deploy 範例指令是 npm run test，與部署不符；沒有說明分析方法。
- 處理：保留作者提出的「六個面向」與三層邊界等做法建議，但在簡報與 wiki 都標明「沒有公開方法，不是實驗證明」。「2,500+」只當作者自述的樣本數。

## C5　「優先」這個詞三家講的機制不同
- S2：最近的那份優先。S5：串接，越近的排越後所以蓋過前面。S4：串接不是覆蓋，最近的最後讀。
- 處理：共通點寫成「越靠近工作位置越優先」，但分開寫各工具機制，簡報不用「覆蓋」一詞概括 Claude Code。
